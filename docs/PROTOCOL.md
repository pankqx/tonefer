# tonefer protocol (v1)

This is what any phone client — the web view today, the native Android app later — must speak.

## Keys

- `key`: 32 random bytes, generated by the laptop. It is shared by QR as `http://<laptop-ip>:<port>/#k=<base64url(key), no padding>`.
- `token` = first 64 hex chars of `SHA-512(key || "tonefer-auth")`. It is an access gate only. Security comes from `key`.
- `seal(bytes)` = `nonce(24 random bytes) || secretbox(bytes, nonce, key)`. This is NaCl secretbox (XSalsa20-Poly1305), and libsodium, PyNaCl and tweetnacl all interoperate.
- `sealJson(obj)` = `base64(seal(utf8(JSON)))`, using standard base64.

## Endpoints (phone side)

The token goes in the `X-Tonefer-Token` header, or `?t=` for WebSocket.

| Method | Path | Body / result |
|---|---|---|
| GET | `/api/ping` | `200` if paired, `401` if not (re-pair) |
| WS | `/ws?t=<token>` | every frame is `sealJson(event)` in both directions |
| POST | `/api/upload` | header `X-Tonefer-Meta: sealJson({name, mime})`, body `seal(file bytes)` |
| GET | `/api/file/<id>` | returns `seal(file bytes)` |

## WebSocket events

Laptop → phone:

- `{type:"hello", host, items:[Item]}` — sent on connect, with the full history
- `{type:"item", item:Item}`
- `{type:"deleted", id}`
- `{type:"cleared"}`

Phone → laptop:

- `{type:"text", text}`

A frame that fails to decrypt closes the socket with code `4001`. Unpairing also closes it with `4001`, and later requests get `401`.
